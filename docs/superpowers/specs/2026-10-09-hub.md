# Hub 0.3.0 coordinated milestone

Retain native WinForms and all 0.2 offline import, corrupt-settings preservation, component verification and atomic installation behaviors. Present forest/cream/brass dark surfaces with readable responsive controls and keyboard access. Product information comes from the shared signed catalog schema 1, never invented install readiness. Genesis schema 1 remains unchanged. Imported installations remain explicitly unverified.

Self-update uses a separate self-contained bootstrapper; Hub never overwrites its running executable. A Hub-specific RSA-PSS signed manifest binds installer bytes, expiry, increasing sequence, provenance, minimum Hub/Windows requirements and a known Authenticode publisher SHA256 certificate pin. The public key and publisher pin are embedded independently at build time; absence disables the entire path before download. Bootstrapper waits for the exact originating process to exit, independently reverifies metadata/installer/Windows signature, then starts the installer. Stage failures preserve current Hub. Installer execution requires user confirmation. This is single-role metadata trust, not TUF; root rotation/revocation and same-version metadata renewal remain operational gaps.

Storage management removes only generated cache/staging under the installation lock, preserves active/previous versions and saves. Location preference affects new installs, cannot silently relocate managed files. UI Windows screenshots are private CI artifacts; Linux compilation cannot establish visual acceptance.

Root approved a narrow forward transition after independent Genesis verification: exactly Genesis0.3.0/saveSchema1→Genesis0.4.0/saveSchema4 with minimumHub0.3 and full save backup. Game import is explicit/read-only into a new profile; Continue does not automatically import. All other cross-epoch changes/rollback stay blocked.
